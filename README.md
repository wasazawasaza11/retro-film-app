# Retro Film

iPhoneの写真を端末内でレトロ調に加工する静止画PWA。外部フレームワーク、CDN、画像アップロード、分析通信は使用しません。動画MP4書き出しにはMPL-2.0のMediabunny 1.61.6をローカル同梱しています。Bulk Mosaic Toolとは独立しています。

## 起動

このフォルダーを静的HTTPサーバーで配信してください。PC上の確認は `npx --yes http-server . -p 8080` などで `http://localhost:8080` を開きます（サーバーツールは開発用で、アプリの依存ではありません）。iPhoneからは **HTTPS** で配信したURLをSafariで開き、「共有 → ホーム画面に追加」。LAN内の通常HTTPではService Workerを利用できません。file://での直接起動にも対応しません。

初回のService Worker登録・キャッシュ完了後にオフライン起動できます。写真はページセッション内のみ保持し、終了後は再選択が必要です。更新時は `sw.js` のキャッシュバージョンを変更し、アプリのファイルをすべて一緒に配信してください。

### Service Workerと開発中の更新

現在のキャッシュ名は `retro-film-cache-v13` です。インストール時はHTML・CSS・全JS・manifest・アイコンをHTTPキャッシュに頼らず取得し、アプリの全ファイルの取得成功後に新Workerを待機させず有効化します。activateでこのアプリの旧 `retro-film-*` キャッシュ（旧 `retro-film-v4` などを含む）を削除し、他アプリのキャッシュは削除しません。

アプリのHTML・CSS・JSなどは **network-first** です。オンラインで開き直すとネットワーク優先で最新ファイルを取得して現行キャッシュへ保存し、通信失敗または3.5秒のタイムアウト時は現行キャッシュでオフライン起動します。旧キャッシュを横断検索しません。開発中にファイルを変更した場合も、再読込で最新内容を取り込みます。新しいバージョンを公開する時は引き続きキャッシュ名を更新してください。

登録は `updateViaCache: 'none'` とし、起動時にWorkerの更新確認を行います。`sw.js` 自体はアプリキャッシュへ入れません。配信サーバーで設定できる場合は `sw.js` に `Cache-Control: no-cache`、開発中のHTML/CSS/JSにも `no-cache` または `no-store` を指定してください。Windowsの開発サーバーは下記の `-c-1` 指定でHTTPキャッシュを無効化できます。

**ページは自動再読込しません。** Workerが新しくなっても既に表示中の画面・実行中のJSはそのままです。作業中の写真を先に書き出し、オンラインでSafariのページを再読込してください。ホーム画面アプリの場合はアプリを終了して開き直します。オフラインのままでは新しいファイルを取得できません。

### iPhoneで旧画面が残る場合のキャッシュ削除手順

1. 先に加工済み写真を書き出します。再読込やサイトデータ削除で、ページ内だけにある編集状態は失われます。写真ライブラリの元画像や保存済み写真を削除する操作ではありません。
2. 配信元が最新の `sw.js`・`index.html`・`css/`・`js/` を公開していることを確認し、iPhoneをオンラインにします。古いURLや別の配信元を開いていないかも確認します。
3. Retro Filmを開いているSafariタブを閉じ、ホーム画面から起動したRetro Filmもアプリスイッチャーで終了します。
4. iPhoneの **設定 → アプリ → Safari → 詳細 → Webサイトデータ** を開きます。iOSのバージョンによっては **設定 → Safari → 詳細 → Webサイトデータ** です。
5. 利用中のドメインを探し、そのサイトのデータを削除します。LAN接続ならPCのIPv4、GitHub Pagesなら `<ユーザー名>.github.io` が目安です。同じサイトのCookieや保存データも削除されるため、他のサイトを含む「すべて削除」は通常不要です。[AppleのSafariキャッシュ削除手順](https://support.apple.com/ja-jp/105082)も参照してください。
6. Safariで最新URLを開き直します。新画面は、写真を大きく表示し、下部に「調整・トリミング・比較・書き出し」の4アイコンがある画面です。右側の丸いプリセットホイールはありません。
7. ホーム画面のアプリだけが古いままの場合は、そのホーム画面アイコンを削除し、Safariで最新画面を確認してから「共有 → ホーム画面に追加」で作り直します。サイトデータの扱いはiOSによって異なるため、Safariのデータ削除だけでホーム画面アプリ側も消去されたと断定しないでください。
8. HTTPS配信で初回キャッシュの準備後、アプリを開き直してオフライン起動を確認します。LAN内のHTTPはService Workerを登録しないため、その接続で旧画面が出る場合は配信ファイル・HTTPキャッシュ・URLを確認してください。

### Windows：同一Wi-FiのiPhoneから開く

1. Windows PCとiPhoneを同じWi-Fiに接続します。
2. PowerShellを開き、配信するフォルダーに移動します。

   ```powershell
   Set-Location 'C:\bulk-mosaic-tool\retro-film-app'
   ```

3. 開発サーバーを **0.0.0.0:8087** で起動します。Node.js / npmがインストールされている場合：

   ```powershell
   npx --yes http-server . -a 0.0.0.0 -p 8087 -c-1
   ```

   Pythonがインストールされている場合は、代わりに次のコマンドでも起動できます。どちらか一方だけを実行します。

   ```powershell
   py -m http.server 8087 --bind 0.0.0.0
   ```

   `0.0.0.0` は全ネットワークインターフェースで待ち受ける指定です。ブラウザに入力するアクセス先ではありません。サーバーのPowerShellは開いたままにし、終了時は `Ctrl+C` を押します。既に8087番でサーバーが動いている場合は、その起動元で停止してから起動し直してください。`127.0.0.1` だけで待ち受けるサーバーにはiPhoneから接続できません。

4. 別のPowerShellでPCのIPv4アドレスを確認します。

   ```powershell
   ipconfig
   ```

   接続中のWi-Fiアダプターに表示された **IPv4 アドレス** を使います。例：`192.168.1.23`。VPN・仮想アダプターのアドレスや、`127.0.0.1` は使いません。
5. iPhone Safariのアドレス欄に次の形式で入力します。

   ```text
   http://<PCのIPv4>:8087
   ```

   例：`http://192.168.1.23:8087/`。PC側は `http://localhost:8087/` でも確認できます。
6. Safariで写真を選び、プレビュー、ホイール操作、JPEG/PNGの書き出しを確認します。写真はiPhone内で処理され、配信元PCにもアップロードされません。

つながらない場合は、Windows Defenderファイアウォールで使用したNode.jsまたはPythonの受信接続をプライベートネットワークに許可しているか確認してください。信頼できる家庭内Wi-Fiを使い、ファイアウォール全体を無効にする必要はありません。ゲストWi-Fiやルーターの端末間通信制限、VPN、PCのスリープも確認します。PCのIPv4アドレスは再接続で変わることがあります。

**LAN内HTTPは操作確認用です。** iPhoneから `http://<PCのIPv4>:8087` にアクセスした場合、Service Workerは登録されず、オフライン起動は確認できません。ホーム画面からのPWA動作・オフライン動作の確認にはHTTPSで配信したURLを使ってください。

### HTTPS公開：GitHub Pages等への配置

アプリは静的なHTML/CSS/JavaScriptだけで構成されており、ビルドやバックエンドなしでGitHub PagesなどのHTTPS対応静的ホスティングへ配置できます。GitHub Pagesは静的ファイルの配信とHTTPSに対応しています：[GitHub Pagesの概要](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)、[HTTPS設定](https://docs.github.com/en/pages/getting-started-with-github-pages/securing-your-github-pages-site-with-https)。

公開するファイルは `index.html`、`manifest.webmanifest`、`sw.js`、`css/`、`js/`、`assets/` です。フォルダー階層と大文字・小文字を維持してください。テスト用の `tests/` は公開に不要です。

- 専用リポジトリの場合：`retro-film-app/` の中身をリポジトリのルートへ置き、GitHubの **Settings → Pages** で公開元ブランチと `/(root)` を選びます。
- このプロジェクト全体を置く場合：公開元がリポジトリのルートなら、アプリは `https://<ユーザー名>.github.io/<リポジトリ名>/retro-film-app/` で開きます。既存のルートの `index.html` はモザイクツールのものなので上書きしません。
- Pagesの公開元フォルダーはルートまたは `/docs` を選べます。任意の `retro-film-app/` 自体を公開元に指定したい場合は、GitHub Actionsでそのフォルダーを静的成果物として配信します。[公開元の設定](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)を参照してください。

公開後は末尾 `/` のあるHTTPS URLを開き、Pagesの **Enforce HTTPS** 設定を確認します。Safariで初回キャッシュ完了後にホーム画面へ追加し、アプリを閉じてから機内モードで起動を確認してください。

パス確認済み：HTMLのCSS・JS・アイコン参照、JSのモジュールimport、Service Workerの登録とキャッシュ一覧、manifestの `id`・`start_url`・`scope`・アイコンはすべて相対パスです。アプリの実行コードにWindows絶対パス、固定localhost URL、ルート固定の `/css/...` などの依存はありません。リポジトリ名やサブディレクトリ名に合わせたコード修正は不要です。READMEのWindowsパスと `tests/browser.cjs` のローカルサーバーURLは開発・検証用で、公開アプリの依存ではありません。今回、PWA・Service Worker・画像処理・UIのコードは変更していません。

## 操作

通常画面はSafe Areaを除く高さのおよそ80%を写真プレビューに、残りを小さなツールバーに使います。写真は初期状態で縦横比を維持したFit表示です。右側の丸いプリセットボタンと展開ホイールは廃止しました。

- **上下スワイプ**：写真上を1本指で下へドラッグすると次、上へドラッグすると前のフィルターへ。8プリセットが循環します。ドラッグを戻すと補間とレンズも戻ります。
- **フリック**：離したときの移動速度を引き継ぎ、指数減衰する慣性で複数プリセットを通過し、最寄りへスナップします。固定個数の切り替えではありません。動きを減らすOS設定では慣性を省略します。
- **巨大レンズ**：下ドラッグでは上から、上ドラッグでは下から流れます。内部は既存エフェクトパイプラインによる隣接プリセットの補間結果で、外側は現在区間の加工結果です。ドラッグ0/50/100%は設定値の0/50/100%補間に対応します。プリセット名は確定後約1.1秒だけ表示します。
- **ピンチ**：2本指でプレビューのみ1〜8倍へ拡大縮小。中心移動も2本指で行えます。ダブルタップでFitへ戻します。ピンチ開始時にフィルタースワイプをキャンセルし、片方の指が残っても全指を離すまでフィルター操作は再開しません。
- **調整**：下部アイコンから強度と11詳細項目のボトムシートを開きます。閉じると写真が広く見えます。強度は原画像と完全加工結果のブレンド率です。プリセットの確定で詳細値をその設定へ戻します。
- **比較**：専用アイコンで加工前／加工後を切り替えます。トリミング済みの場合は同じクロップ構図で比較し、比較中はフィルタースワイプを止めます。長押しとの競合を避けています。
- **トリミング**：Free、1:1、4:3、3:4、16:9、9:16。Freeの幅・高さはスライダーで変更します。枠内の1本指ドラッグで画像位置、2本指ピンチで画像倍率を調整できます。角度は-45〜+45°、90°回転にも対応。フィルタースワイプを無効にし、四隅が原画像内に収まるよう拡大率と移動を制限します。「確定」で反映、「キャンセル」で元の構図を維持します。原画像は変更しません。
- **キーボード**：写真領域にフォーカスして上下矢印で前後のフィルター、Escapeで操作をキャンセルできます。

7つの既存プリセットにフィルム調の **B&W** を追加しています。B&Wは輝度変換・コントラスト・フェード・粒子の組合せです。強度100%で完全な白黒、100%未満では原画像とのブレンドにより色が残ります。モノクロ量はプリセット設定データで管理し、将来のモノクロ追加にも同じ補間・循環処理を利用できます。

粒子・光漏れ・傷・ホコリのシードは写真読込時に生成し、その写真の再描画では維持します。レンズの反射、プレビューのピンチ倍率、比較表示、クロップ枠は書き出しには含まれません。

### 書き出しとiPhone保存

下部の小さな書き出しアイコンを押して設定シートを開きます。JPEG（初期品質90%）またはPNGを選び、原画像解像度で処理したファイルの準備完了を待ってください。クロップ済みなら原画像座標のクロップ出力サイズを使います。

`navigator.canShare({files:[file]})` で実際の加工ファイルを検査し、対応環境では **「共有して保存」** からWeb Share APIでiOS共有シートを開きます。共有先に「画像を保存」が表示される場合は、それを選択してください。写真ライブラリへの直接書き込みは行いません。共有完了は写真保存完了を意味せず、アプリでは保存先の結果を確認できません。

[Web Share APIはHTTPSとユーザー操作直後の呼び出しを必要とします](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/share)。元解像度処理でその操作権限を失わないよう、先にファイルを生成し、準備後のボタン操作で共有を呼びます。非対応環境（LAN内のHTTPを含む）ではダウンロードへ切り替え、共有の失敗時にも保存リンクを表示します。共有のキャンセル時は自動ダウンロードしません。

## モジュール

- `index.html` / `css/style.css`：写真中心の画面、Safe Area、ツールバー、ボトムシート、クロップ枠
- `js/app.js`：UI・写真セッション・表示専用ズーム・非破壊クロップ・共有準備の接続
- `js/image-loader.js`：ローカル画像デコード、解放、画像シード（既存処理を維持）
- `js/photo-gestures.js`：1本指スワイプ、実測速度の慣性、スナップ、ピンチ排他、Fit復帰
- `js/lens.js`：上下から流れる巨大レンズの共有幾何
- `js/crop.js`：原画像座標のクロップ、回転、四隅による制約、プレビュー／出力共通描画
- `js/renderer.js`：最大辺800pxの加工プレビュー、rAF更新集約、レンズ内の加工結果描画
- `js/effects.js`：再利用可能なフレーム処理とモノクロ変換
- `js/presets.js`：既存7プリセット＋B&W、11詳細項目、補間
- `js/exporter.js`：元解像度JPEG/PNG、同じクロップ処理、共有可能なFileの検査
- `manifest.webmanifest` / `sw.js`：standalone・オフライン。新しいジェスチャーとクロップモジュールもキャッシュします。
- `assets/icons/`：既存のSVG原稿、192px/512px PNGアイコン

## 制限・実機確認

現在のSafariとChrome向け。HEICなどは端末の画像デコーダー対応に依存します。JPEG/PNG/WebPを基本対象とします。Canvasによる再エンコードではEXIFなどのメタデータは保持しません。画像全体を保持するため大画像は端末のメモリ・Canvasサイズ上限で失敗する場合があります。書き出しの画素処理はメインスレッドで行い、大画像では一時的に操作を待つことがあります。

SNS連携、アカウント、クラウド、AI、複数画像処理は未実装。動画プレビューも `processFrame(source, width, height, parameters, seed, intensity)` を再利用する構造です。粒子・傷などは正規化座標で近い外観を再現しますが、プレビューと原寸で画素単位の一致はしません。

### 手動テスト・iPhone Safari実機確認

1. JPEG/PNG/WebP、縦横写真、EXIF回転写真を選び、Safe AreaとSafariのアドレスバー変化を含めてFit表示・約80%の写真領域を確認。
2. 下・上のゆっくりドラッグ、途中で戻す操作、速さの異なるフリックを確認。慣性中に次々レンズが流れ、速度に応じて移動量が変わり、最後に確定して名前が消えることを確認。
3. 1本指ドラッグ中に2本指へ切り替え、ピンチ後に片指だけ残して動かす。誤ったフィルター確定がないこと、Fit復帰、1〜8倍表示と指中心のズームを確認。
4. 調整シートの強度0/70/100と全11項目、スクロール、閉じる操作を確認。強度0で原画像、100でB&Wの白黒を確認し、再描画の模様がちらつかないことを確認。
5. Freeの枠サイズ、全5固定比率、1本指の位置移動、クロップ中のピンチ、±45°と90°回転を確認。「キャンセル」が構図を変更しないこと、回転後の出力に新しい透明領域がないことを確認。
6. 比較アイコンの加工前／後で同じ構図を維持することを確認。通常ピンチ後の書き出しでも出力寸法が変わらないことを確認。
7. HTTPSのSafariとホーム画面PWAでJPEG/PNGのFile共有を行い、iOS共有シート内の「画像を保存」と写真アプリでの実保存を確認。品質変更、共有キャンセル、共有非対応時のダウンロードも確認。
8. 初回キャッシュ完了後に全ウィンドウを閉じ、機内モードでホーム画面から起動。写真選択、調整、クロップ、書き出しまで確認。
9. 数千万画素の写真でメモリ・処理時間・共有成功を確認。ブラウザコンソールと通信に画像・名前・加工結果の送信がないことを確認。

通常は巨大レンズ直径を表示写真幅の2.2倍とします。極端に細長い写真では「最後に四隅までレンズ内に入る」条件を優先して直径を増やします。プレビューと原寸で粒子は近い外観になりますが、画素単位の一致はしません。プレビュー用ピンチ倍率とクロップ用倍率は独立しています。クロップは原画像から処理し、プレビュー拡大のピクセルを保存しません。

### 自動検証

`tests/browser.cjs` はPlaywrightとインストール済みMicrosoft Edgeで実行します。アプリ自体にテスト依存はありません。ローカルサーバーを8087番で起動し、Playwrightが通常のモジュール探索で見つからない場合は `PLAYWRIGHT_PATH` にそのパッケージの絶対パスを指定します。

`tests/service-worker.cjs` は専用のローカルサーバー（127.0.0.1:8089、テスト終了時に停止）で、旧v4のページを開いたままv12へ更新する状況を再現します。旧キャッシュ削除、他アプリのキャッシュ維持、全24ファイルの再取得、長いHTTPキャッシュ期間が設定されていてもHTML/CSS/JSが更新されること、自動再読込をしないこと、Worker自身をキャッシュしないこと、更新後のオフライン利用を検証しています。

確認済み：JPEG/PNG/WebP、写真領域比率、直接ドラッグと巻き戻し、実測速度での慣性、ピンチへの切替と残った指の排他、Fit復帰、強度と11調整、シードの安定性、全固定比率とFree、クロップ取消、複数回転角での四隅制約と不透明出力、JPEG/PNGの実ダウンロード、プレビュー拡大と独立した元解像度出力、B&Wと循環、比較、共有File・ユーザー操作権限・キャンセル（OS共有境界を模擬）、オフライン再読込、コンソールエラーなし、ローカルGET通信のみ。

iPhoneの実タッチ・OS共有シート・写真ライブラリ保存は模擬検証で代替できず、実機確認は未実施です。大画像は端末性能に依存し、元解像度処理中に一時的に操作を待つ場合があります。

### LAN開発の配信を確実に更新する

現在の開発用起動方法は `py C:\bulk-mosaic-tool\retro-film-app\dev-server.py` です。起動位置に関係なく、このスクリプトのあるretro-film-appフォルダーを0.0.0.0:8087で配信します。8087を使用する旧サーバーは先に停止してください。

確認用URL：`http://192.168.50.2:8087/?v=20261004-2`。DEBUGはこのURLでは非表示です。診断時だけ `&debug=1` を追加します。HTMLのv指定だけでは内部importを更新できないため、各CSS/JS URLにもバージョンを付けています。

### プリセット別の調整とお気に入り

各プリセットの詳細値は元のデフォルトと別に保持します。調整内の「初期値に戻す」は現在のプリセットだけを戻します。★1〜★3は呼び出し、保存先を選んで「保存」で現在のbase preset・強度・全詳細値（B&Wを含む）を登録します。登録済み枠への保存は上書き確認を行います。

保存キーは `retroFilm.adjustments.v1`。形式は `{overrides: {presetName: values}, favorites: [{preset, strength, values}, null, null]}`。写真・名前・クロップ・ズームは保存しません。ストレージ利用不可時もセッション中は保持しますが、再起動後の保存は保証できません。

調整シートのbackdropは透明で、写真を暗くしません。フリックのrelease後は、位置の最寄り整数を現在の基準とし、速度が閾値を超えれば速度方向の次の整数、それ以外は最寄りへスナップします。ドラッグ中に複数枚を通過しても、release後に複数枚を自動通過しません。

最新版確認URLは `http://192.168.50.2:8087/?v=20261004-4`。角度診断時だけ `&debug=1` を追加。ANGLE FRAMEは実描画後のstate、crop rect、Canvas属性/CSS寸法、wrapper矩形/transform、viewport/scroll、draw座標、render source/回数を記録します。ログは画面内に限定し最大160行、外部送信しません。

## 動画プレビュー（Phase 1・2）

「写真を選ぶ」から写真または動画を選べます。動画は最初のフレームをCanvas表示し、下端の▶で再生、Ⅱで停止、シークバーで移動します。再生中も既存のプリセットスワイプ・巨大レンズ・詳細調整・お気に入り・B&W・表示専用ピンチを使えます。音声は元動画の再生音声です。動画のcropは未対応のためcropアイコンだけ無効になります。動画の書き出しはMP4専用の設定シートで行います。写真へ切り替えれば従来どおり利用できます。

推奨は1080p以下・30fps程度・60秒以内。MP4/MOVの対応コーデックはブラウザに依存し、大きい動画では警告を表示します。動画プレビューは最大辺640px、端末負荷によってフレームが落ちる場合があります。既存エフェクトを共有し、動画だけ時間・輝度・動きに応じた緩やかな変化を適用します。写真は固定seedです。

すべて端末内処理です。動画をアップロード・自動保存・Service Workerキャッシュへ保存しません。オンラインでアプリを準備した後は、端末内で利用可能な動画をオフラインで選べます。動画ファイルはページ終了後に再選択します。

実装構造、Phase別検証結果、iPhone実機チェックリストは[VIDEO-PHASES.md](VIDEO-PHASES.md)に記載しています。現在の配信版は `?v=20261024-1`、Workerはv13・24アセットです。既存のGitHub Pagesサブパスと相対importを維持しています。公開先へのpushはこの変更では実施していません。


## 動画をMP4へ書き出す（Phase 3・4 ローカル実装）

動画を選択→書き出しアイコン→元/1080p/720p・高/標準→「MP4を生成」。進捗と処理時間を表示し、キャンセル可能です。元解像度が小さい場合は拡大しません。選択した動画全体を対象とし、表示専用ピンチは出力に影響しません。元動画の主要音声は保持し、AACなら可能な限りコピー、それ以外はAACへ変換します。音声を保持できない場合は無音化せずエラーにします。

生成後の「共有して保存」で、HTTPS対応環境なら標準共有シートを開き「ビデオを保存」を選べます。共有完了は写真アプリへの保存確認とは異なります。写真アプリで向き・音声・色を確認してください。共有キャンセルではdownloadしません。API非対応/共有失敗時は従来downloadへ戻ります。LAN HTTPではWeb Share APIを利用できません。

WebCodecsの対象H.264設定/入力decodeが非対応の場合はMP4生成を止めます。?debug=1の能力レポートを確認してください。MediaRecorderやWebMへ自動で方式を変更しません。iPhone Safari/PWAでのMP4生成・音声・「ビデオを保存」は未検証です。まず音声あり縦1080p・30fps・10〜15秒で確認してください。4K/長尺はメモリと処理時間が増えます。プレビューは引き続き最大辺640pxです。

[VIDEO-EXPORT.md](VIDEO-EXPORT.md)に採用方式・capability実測・メモリ・キャンセル・実機手順をまとめています。追加依存の[Mediabunny配布情報/ライセンス](vendor/mediabunny/NOTICE.md)と[対応ソース](vendor/mediabunny/upstream-1.61.6.tgz)を同梱しています。app shellにはローカルbundleを含めますが、選択動画や出力MP4はキャッシュしません。公開時はvendorフォルダーも含めて一式配信してください。


## 動画の軽量書き出しと動くフィルム効果

動画出力に480p・360p・240p、24/15/12fps、低画質を追加しました。初期値は480p・24fps・低画質です。「軽量・VHS向け」で480p・15fpsへ切り替えられます。元/1080p/720p・元fps・高/標準も残しています。小さい入力や低fps入力は拡大・増fpsしません。fpsを減らしても再生速度・動画長・音声の速度は変えません。プレビュー再生は従来の元fpsで、選んだ低fpsは書き出しへ反映します。

画素数とフレーム数を減らすと加工負荷を減らせます。低画質だけの変更は主にファイルサイズへ作用します。画面の「画素×fps」は処理量の概算で、完了時間の予測ではありません。まず480p/15fps、さらに軽くするなら360p/12fpsをお試しください。

動画の粒子は約12Hz、傷は約0.33秒、ホコリは約1.1秒の独立した周期で変わり、光漏れは数秒かけてゆっくり動きます。32×24の小さな解析画面で明るさ変化と画面の平行移動を推定し、効果の位置・強さだけに弱く反映します。写真本体を揺らしたり、写真の固定seedを変えたりしません。強度0は従来どおり元映像です。

変化はmedia timeとseedから生成し、プレビュー/書き出しで同じルールを使います。同じ入力・seed・出力設定の再出力は再現可能です。低fps出力とプレビューでは前フレームの間隔が違うため、動き推定の弱い補正まで完全な画素一致にはなりません。追加の動画保存・アップロード・依存ライブラリはありません。


動画の書き出し音声は「元のまま」「カセット」「VHS」「古いラジオ」から選べます。音声加工は書き出し時のみ適用し、プレビューは元音声です。レトロ音声はモノラル化・帯域制限・軽い歪み・ノイズで質感を変え、再生速度や長さは変えません。「元のまま」が最も軽い設定です。詳しくは [動画書き出し](VIDEO-EXPORT.md) を参照してください。
